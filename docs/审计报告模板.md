# 审计报告模板（六段式）

> 每轮审查固定按本模板输出，便于第三方复验与逐轮差分。参照正泰 8 相机版多轮审计实践。
> 核心原则：**不把历史结论自动当成"已修复"，全部按当前源码重新判定**。

## 1. 本轮基线

- 审查日期 / 对象 / 范围（参与编译文件数、关键文件行数）
- 构建：命令、退出码、产物隔离目录、日志文件名
- 测试：命令，通过数 / 总数（以实测输出为准，不手写在注释里）
- 源码基线：`audit-baseline.json`（由 `.\verify.ps1 -GenerateBaseline` 生成，相对路径 + SHA-256）

## 2. 验证边界与未做的事

明确列出未纳入验证的范围，例如：第三方 DLL 内部实现、VPP 内嵌脚本、真实相机/PLC 时序、未启动检测程序。
**未做的验证不要写成"已验证"。**

## 3. 上轮问题逐条状态对照

| 编号 | 上轮结论 | 本轮状态（已修复 / 部分 / 保留） | 当前证据（文件:行号） |
|---|---|---|---|

> 上轮编号与后续编号不是一一对应、互不重叠的集合，**不能直接相加**。
> 不要写"12 项彻底消除 + 4 项完全闭合 = 只余五项"这类过度汇总。

## 4. 本轮确定缺陷

按 P0 / P1 / P2 分级，每条给出：文件:行号 + 复现条件 + 影响 + 建议。
并发结论尽量用独立最小复现支撑，而非仅凭源码推演；并注明"验证的是软件控制流，不代表做过硬件联机复现"。

## 5. 存疑项（需现场/压测验证，不计入确定缺陷）

只写证据不足以定论的点，并注明需要什么条件才能验证（真机长稳、4K 相机、慢速磁盘等）。

## 6. 复核方法与可信度

- 用了什么手段：静态阅读 / 最小复现 / 单元测试 / 真机压测
- 结论的置信度，以及哪些部分不可外推到其它配置
- 如果本轮没有跑构建或测试，明确写出来
