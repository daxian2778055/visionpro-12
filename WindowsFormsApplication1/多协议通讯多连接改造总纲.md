# 多协议通讯多连接改造总纲

> 适用范围：**Modbus TCP、FINS、Modbus RTU、无协议（串口/TCP）** 四种通讯，统一按同一套思路改造，支持每种协议连接**多个服务器/设备**。
> 本文档是总纲（框架 + 各协议差异 + 路线），各协议具体的实施细节见其分文档。
> Modbus TCP 的详细设计见 `多连接改造方案-ModbusTCP.md`，本文档引用之。

---

## 0. 背景与目标

现状：四种通讯目前都是**单实例**——每种协议在界面上只能配 1 台设备（1 个服务器 / 1 个串口 / 1 个 TCP 端点），触发、切型、反馈全固定绑在这唯一一台上。

目标：每种协议都能配置**多台设备**，各自独立：
- 独立 IP / 端口 / 串口 / 轮询参数
- 独立触发所管理的相机
- 独立回写 OK/NG 结果
- 全局切型排队，防止多台同时切换方案打架

约束（来自前几轮评估）：底层库（HslCommunication）本身支持多客户端实例，技术可行；难点在**应用层把"连接 / 触发 / 切型 / 反馈 / 配置"绑死成 1:1:1:1:1**，必须先解耦再上多实例。

---

## 1. 统一改造思路（通用模板）

四种协议代码结构高度相似（都是"窗体既显示界面又干活"的同一种代码复制改改），因此**每改造一种协议，都照下面六步模板走一次**。每步保持「行为不变 + 可独立编译验证 + 可回退」。

| 子阶段 | 做什么 | 风险 | 验收 |
|---|---|---|---|
| **A** | 配置模型类 + 多段 ini 读写（只读写，不接线） | 低 | 启动不报错，配置正确加载/保存，老配置零改动 |
| **B** | 把"干活逻辑"从窗体抽到独立**运行时引擎**（仍只有 1 个连接） | **高** | **必须实机**：连接/触发/拍照/反馈/切型与改造前完全一致 |
| **C** | 运行时引擎支持**多个实例同时运行** | 中 | 多台设备各自触发各自相机，互不干扰 |
| **D** | **界面增删连接** + 相机分组配置 | 中 | 能加/删，最少保留 1 个，配置正确保存/加载 |
| **E** | 反馈归属路由 + 切型全局排队仲裁 | 中 | 结果不错连；多台同时切型不打架 |
| **F** | 收尾（修已知 bug、清理遗留键、写分文档） | 低 | — |

> 已建好的**公共地基**（阶段 1 之前已完成，编译 0 错误、行为不变）：
> - `Services/ModbusTcpLink.cs`：连接封装（建链/断链/重连 + 参数），实现 `ICommLink`
> - `Services/ICommLink.cs`：统一连接接口（LinkId / Name / Protocol / IsConnected / Close / Reconnect）
> - `Services/CommLinkManager.cs`：连接注册表（按 LinkId 登记、查找、管理）
> - `FormModbus.cs`：连接改由 `ModbusTcpLink` 持有；触发事件已带 `LinkId`
> - `CommunicationService.cs`：已建立注册表并登记现有连接

## 2. 各协议现状对照表

| 协议 | 窗体文件 | 连接对象（类型） | 连接类别 | 配置段模式（连接 1 / 连接 n） | 多实例硬阻碍 | 与 Modbus TCP 相似度 |
|---|---|---|---|---|---|---|
| **Modbus TCP** | `FormModbus.cs` | `ModbusTcpNet` | 网络 | `[modbustcp]` / `[modbustcp2]`；数据块 `[N_modbustcp]` / `[N_modbustcp2]`；相机 `[cN_modbustcp]` / `[cN_modbustcp2]`；切型 `[change_modbustcp]`；路径 `[path_modbustcp]` | 无（不同 IP 即可） | 基准 |
| **FINS** | `FormOmron.cs` | `OmronFinsNet` | 网络 | `[fins]` / `[finsN]`；数据块 `[N]`(连接1纯数字) / `[N_finsN]`；相机 `[cN]` / `[cN_finsN]`；切型 `[change]`(连接1，**实测无 fins 后缀，与无协议共用同名段**) / `[change_finsN]`；路径 `[path]`(连接1，**实测无 fins 后缀，与无协议共用同名段**) / `[path_finsN]` | 无（网络） | 高（同 HslCommunication，结构几乎一样） |
| **Modbus RTU** | `FormModbusRtu.cs` | `ModbusRtu`（走 `SerialPort`） | **串口** | `[modbusrtu]` / `[modbusrtuN]`；数据块 `[Nmodbusrtu]`（**无下划线**）/ `[NmodbusrtuN]`；相机 `[cNmodbusrtu]`（无下划线）/ `[cNmodbusrtuN]`；切型 `[changemodbustcp]`?；路径 `[pathmodbusrtu]` | **串口独占**：一个 COM 口同一时刻只能被一个实例打开，多实例必须不同 COM 口 | 高（同 HslCommunication） |
| **无协议** | `Form3.cs` | `SerialPort` + `Socket`（TCP 服务/客户端） | 串口 + TCP | `[serial]` / `[tcpclient]` / `[tcpserver]` / `[tcpsend]` / `[change]` / `[path]` / `[out0]~[out3]` / `[jinzhi]` | **5 个 static 串口参数**（`Form3.cs:56-60`：strportName/strbaudRate/strDataBits/strStopBits/strjiaoyan），多实例会互相覆盖，必须先改成实例字段 | 低（裸数据字符串模型，触发靠字符串比对） |

> 标注 `*` 的 FINS 段名（数据块/切型/路径）为按既有代码推断，**实施 FINS 阶段前会再用 PowerShell 精确核对一次**。

### 2.1 各协议特殊难点

- **Modbus RTU（串口独占）**：串口是独占资源，`new ModbusRtu(station)` 后 `SerialPortInni(sp => sp.PortName = ...)` 打开的是具体 COM 口。因此"多实例"在 RTU 上的实际含义是**接多个串口**（多个 COM 口、或多个串口服务器映射出不同 COM），而不是同一 COM 口接多台。实施时需在 UI 上明确每台连接的 COM 口，并做"COM 口不可重复占用"的校验。

- **无协议（static 串口参数 + 两套通讯并存）**：`Form3.cs` 同时管串口和 TCP 两套通讯，且串口参数用 `static` 全局变量，任何"多串口"都会互相覆盖。改造无协议前**必须先消除 static**（把 5 个参数改为实例字段，保存/读取各自走自己的配置段）。另外无协议的 TCP 服务端（`serverSocket` 字典）已经支持多客户端连接，这部分可保留。

- **FINS**：网络协议、无 static 阻碍，且用的是和 Modbus TCP 同一套 HslCommunication，代码几乎一样，是四种里最顺的一个。

- **无协议触发模型不同**：Modbus 系列是"寄存器地址 + 数值"触发；无协议是"收到字符串 → 比对该相机的触发字符 → 触发"。无协议已经支持"每台相机不同触发字符、留空=任意"（前几轮已改好）。多实例时，这个逐相机比对逻辑照搬即可，只是每个串口/TCP 端点各自一个实例。

## 3. 跨协议共享机制（全局统一，不按协议各做一套）

### 3.1 连接注册表 `CommLinkManager`（已建好，跨协议通用）

所有协议的连接实例（无论 `ModbusTcpLink` / `FinsLink` / `RtuLink` / `RawLink`）都实现 `ICommLink`，登记进同一个 `CommLinkManager`，按 `LinkId` 索引。上层（触发路由、反馈回写、切型仲裁）只面向 `ICommLink` 编程。

### 3.2 相机分组与反馈路由（全局分组表）

"某台相机归哪个连接管"是**跨协议的全局信息**，需一张统一的总览表（建议放在新的 `[comm_links]` 段，覆盖全部协议）：

```ini
[comm_links]
count=3
link1=modbustcp      ; 协议类型
link2=modbustcp
link3=fins
name1=1号线PLC
name2=2号线PLC
name3=欧姆龙PLC
cameras1=1,2,3,4,5,6
cameras2=7,8,9,10,11,12
cameras3=1,2,3,4,5,6
```

- 触发：某连接收到触发 → 只在该连接 `camerasN` 范围内的相机里比对触发条件并拍照。
- 反馈：某相机判定完成 → 回写给"该相机所属连接"（按 `camerasN` 反查对应 `LinkId`，再经 `CommLinkManager` 找到运行时实例回写）。
- **建议相机分组强制互斥**（一台相机只属于一个连接），避免"结果回给谁"歧义。

### 3.3 切型全局仲裁（一把锁，跨协议统一）

切型 = "切换视觉方案"，一台机器同一时刻只能跑一个方案。无论触发来自哪个协议、哪个连接，**所有切型请求统一进一个全局队列，由一把全局锁串行处理**：

```
连接A(任意协议)下发切型 → 入队 → 获得锁 → 开始切换
连接B(任意协议)同时下发 → 排队等待（或超时记录日志并放弃）
                    → 连接A切完释放锁 → 连接B再切
```

切型字符 → 方案路径的映射表，由**下发连接的自身配置段**提供（每个连接有自己的 `[change_x]`/`[path_x]`）。

## 4. 配置命名总规则

通用原则：**连接 1 沿用现有段名（空后缀，零迁移）；连接 2+ 在"能区分的位置"加数字后缀**。

| 协议 | 连接 1（兼容现有） | 连接 2 |
|---|---|---|
| Modbus TCP | `[modbustcp]` / `[N_modbustcp]` / `[cN_modbustcp]` | `[modbustcp2]` / `[N_modbustcp2]` / `[cN_modbustcp2]` |
| FINS | `[fins]` / `[N]` / `[cN]` | `[fins2]` / `[N_fins2]` / `[cN_fins2]` |
| Modbus RTU | `[modbusrtu]` / `[Nmodbusrtu]` / `[cNmodbusrtu]` | `[modbusrtu2]` / `[Nmodbusrtu2]` / `[cNmodbusrtu2]` |
| 无协议 | `[serial]` / `[tcpclient]` / `[change]` / `[path]` | `[serial2]` / `[tcpclient2]` / `[change2]` / `[path2]` |

> 各协议"后缀插入点"不同（TCP 是段名整体追加，FINS 数据块在 `[N]` 后追加，RTU 在 `[Nmodbusrtu]` 后追加），具体由 `XxxIniStore` 在各自实施阶段实现，但都遵循"连接 1 空后缀"的兼容原则。
> 各协议的 `XxxIniStore` 负责 Load/Save/LoadAll/SaveAll/Delete(LinkId)，并处理兼容。

```

  │     →  D 界面增删+相机分组  →  E 反馈路由+切型仲裁  →  F 收尾
  │
  ├─ 阶段 3：FINS（最顺，同 HslCommunication）
  │     同 A→F 模板，段名按第 2 节表
  │
```

## 6. 风险与注意事项

1. **阶段 B（抽运行时引擎）是每协议最高风险点**，必须实机验证通过再叠加多实例。
2. **Modbus RTU 串口独占**：多实例 = 多 COM 口；UI 需校验 COM 口不重复占用，并提示用户"同一串口不能同时被两个连接打开"。
3. **无协议 static 串口参数**：`Form3.cs:56-60` 是硬阻塞，改造前必须改为实例字段，否则多串口互相覆盖参数。
4. **线程**：每连接一个轮询/监听线程，多连接 = 多线程，CPU 与设备压力上升；建议轮询周期错开，连接总数控制在 4 个/协议以内。
5. **既有 bug 会继承**：已知 `FormModbus.cs` 的 `c13` 有重复写点、`Form3` 无协议配置段混合，多实例改造时顺手修。
6. **老配置兼容**：所有协议的连接 1 都沿用现有段名，不破坏现有 `test.ini`。
7. **不要一次改多个协议**：先只做 Modbus TCP 跑稳，再 FINS → RTU → 无协议，逐个验收。

## 7. 全局决策（已确认 · 2026-09-04）

> 以下 4 项已在改造启动前由用户确认，作为后续所有协议（FINS / Modbus RTU / 无协议）的实施约束。

1. **相机分组强制互斥**：✅ 已确认 —— 一台相机只属于一个连接，结果归属唯一（避免"回写给谁"歧义）。
2. **每协议连接上限**：✅ 已确认 = **4 个/协议**（性能与可操作性平衡）。
3. **Modbus RTU 多实例形态**：✅ 已确认 = **多 COM 口**（每台连接一个独立串口）；不做"同一串口多站号"（串口独占做不到同一串口多实例同时开）。UI 须校验 COM 口不重复占用。
4. **无协议 TCP 多端点**：✅ 已确认 = 无协议 TCP **需要多 TCP 监听端点（多端口）**，而非仅"单服务端多客户端"。
